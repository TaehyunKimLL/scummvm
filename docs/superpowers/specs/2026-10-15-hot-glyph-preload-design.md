# Hot glyphs: preload what the game draws, stream the rest

Date: 2026-10-15. Branch: jamo. Status: design, revised 2026-10-15 (preload list instead of a baked hot prefix; approved in direction by the user: "정적분석을 해서 미리 메모리에
올릴 문자를 선택하고 없으면 디스크에서 읽게 할까?" -> "응").

## Why

A face is read whole or streamed (`[load]` whole|stream|auto, README "Whole or streamed"). Whole costs the full
2,350-syllable face although a game draws about half (MI2's bundle: 1,194 syllables; a title/card charset only a
few dozen). Streaming costs a disk read the first time each glyph is drawn - on DOS a seek per cache miss. Subsetting
the face (dropping unused glyphs) was rejected: a missed character would have no glyph. Instead: keep every glyph in
the file, and keep in memory only the glyphs a static analysis says the game draws with that face. A wrong guess
costs one disk read, never a box.

## What

### Fonts stay generic; the game ships a preload list

User decision (2026-10-15): "이렇게 하면 폰트를 매번 구워야함. 폰트+로딩할 글자맵 이런식으로 구현하자. Disk IO는 좀
더 느려지지만". A face is shared by games and must not be re-baked when a translation changes, so the hot set is
not in the SVF. The game's pack carries a **preload list** per face, and the map names it:

```ini
[fonts]
dlg=M2U2.SVF
card=M2U7.SVF

[preload]
dlg=data:M2KO2.HOT      ; characters to keep in memory for this face
card=data:M2KO7.HOT
```

- A `.HOT` file is UTF-8 text: the characters, in any order, any line breaks (lines starting with `#` are comments).
  Generated by tools/korean/charsetchars.py from the game's scripts and bundle (union over the charsets that use
  the face, plus ASCII); hand-editable.
- `[preload]` follows `[fonts]`/`[load]` conventions: keys are `[fonts]` names, qualified sections
  (`[preload:clut8]`) overlay, one file per resolved face (two names on one file: first wins, warn), an unknown name or
  an unreadable file warns once and means no preload. A map without `[preload]` loads exactly as before.
- Applies to faces that stream (`stream`, or `auto` above the threshold). A `whole` face (or `auto` below the
  threshold) is entirely in memory already; the list is ignored there.

### The engine

- At open of a streamed face with a list: map each listed code point to its glyph index (cmap), drop those the face
  lacks (a chain's later face can list them too), sort the indices and read them in runs of adjacent indices
  (coalesced reads; glyphs are stored in code-point order, so a game's syllables are scattered - more seeks than a
  contiguous prefix, accepted by the user) into a resident store that the LRU cache never evicts. Other glyphs
  stream through the cache as today.
- Allocation failure: no preload, plain streaming, one warning.
- Prefetch skips resident glyphs. Jamo-set faces: the list's syllables are expanded to their pieces (the pieces are
  what is stored), and pieces are preloaded.
- Debug: `caches all` reports per face: preload list size, resident glyphs/bytes, resident hits, cold misses.

### The analysis (tools)

- Per game and per charset, the set of characters drawn: walk the scripts (tools/korean/scummscript.py), attribute
  each print/text opcode to the charset set before it (conservatively across control flow; undecidable -> every
  candidate charset), map original strings to translations through the bundle (korean.trs), add verb/object names
  and anything else drawn with the charset. Validate against engine text logs from the route runs (every logged line's
  characters must be in its charset's set; report misses).
- The preload list of a face = union of the sets of the charsets that use it (map chains), plus ASCII. Done:
  charsetchars.py (commit 0401275f240). To add: an output mode writing one `.HOT` per face of a map, and
  facecoverage.py reporting list coverage (informational - a miss is a disk read, not a failure). Faces are
  never re-baked for it.

## Measures of success

- MI2 on DOS (DOSBox-X 8 and 16 MB): memory with preload lists vs `[load]` whole/auto, and count of cold reads on the
  standard routes (should be ~0 for dialogue faces).
- Rendering byte-identical to whole loading (dump compare) on the routes.

## Out of scope

- Lazy opening of faces never drawn (separate TODO card t_21701c7a).
- Hot sets for engines other than SCUMM (SCI/AGI read the block; their analysis comes later).
