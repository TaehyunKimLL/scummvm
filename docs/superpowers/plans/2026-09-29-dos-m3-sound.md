# DOS 포트 M3 — 사운드와 선점형 타이머 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DOS 빌드에서 SCI0 음악이 실제 OPL 칩(0x388/SB OPL3) 또는 MPU-401(UART, MT-32/GM)으로 나오고, 음악 타이밍은 1 kHz 보호 모드 IRQ0
핸들러가 선점으로 돌려 방 로딩 중에도 흔들리지 않으며, PCM 은 SDL3 Sound Blaster 로 믹서가 낸다. DOSBox-X·Staging 에서 음표 타이밍 기준을 통과한다.

**Architecture:** `OSystem_DOS` 에 세 매니저를 더한다. (1) `DosTimerManager` — `DefaultTimerManager` 를 상속하고, PIT 채널 0 을 1193 분주(≈1 kHz)로
돌리는 보호 모드 IRQ0 핸들러가 `handler()` 를 부른다; 누산기가 65536 을 넘을 때마다 원래 BIOS INT 8 로 체인하고 아니면 EOI 만 보낸다(M0 스파이크 변형 D).
`getMillis()` 는 이 핸들러의 틱 카운터. (2) `DosMutex` — `pushf; cli` / `popf`. (3) `DosMixerManager` — SDL3 오디오 스트림 콜백이 `MixerImpl::mixCallback`
을 부른다. 음악 장치: `audio/dosopl.cpp` (`OPL::OPL` + `Audio::RealChip`, `fmopl.cpp` 표의 `dosopl`) 과 `backends/midi/dos_mpu401.cpp` (음악 플러그인
`mpu401`). 둘 다 `BLASTER` 환경 변수에서 포트를 읽는다. 엔진은 고치지 않는다.

**Tech Stack:** DJGPP (dpmi.h, go32.h, pc.h), SDL3 DOS 오디오, ScummVM audio/ (OPL, MidiDriver, Mixer), CxxTest, DOSBox-X/Staging (sb16, OPL3, mpu401 uart).

**Spec:** `docs/superpowers/specs/2026-09-28-scummvm-dos-sdl3-design.md` (§5 사운드와 타이머, §8 M3)

- 엔진(`engines/`)은 고치지 않는다. 공통 코드(`audio/`, `base/plugins.cpp`, `configure`)는 DOS 백엔드와 다른 커밋, DOS 전용 코드는 `DOS_DJGPP`/`__DJGPP__` 로 감싼다.
- 타이머 (spec §5.4, M0 스파이크 결론): PIT 분주 1193, 누산 `acc += 1193; if (acc >= 65536) { acc -= 65536; 원래 INT 8 호출(pushfl; lcall) } else outportb(0x20, 0x20)`.
  RTC(IRQ8)는 쓰지 않는다(DOSBox-X 가 멈춤). 종료(정상·`exit()`·`fatalError`) 때 PIT 을 기본(0 = 65536)으로, 벡터를 원래대로 — `atexit` 로 idempotent 하게(COM 의 선례).
- ISR 규칙: 핸들러와 그것이 부르는 모든 코드·데이터는 잠긴 메모리. **ruling:** M3 부터 `main()` 은 `_CRT0_FLAG_LOCK_MEMORY` 를 지우지 않는다 — 이후의
  모든 sbrk 할당이 잠겨 엔진의 타이머 콜백(SCI 음악, OPL 드라이버)이 힙을 만져도 페이지 폴트가 없다(16 MB 에서 허용). ISR 안에서 DOS/BIOS 호출 금지,
  FPU 상태 저장·복원(`fsave`/`frstor`), 재진입 금지(바쁜 동안 들어온 틱은 세기만 하고 다음에 몰아 부른다).
- 뮤텍스: `Common::Mutex` = `pushf; cli` / `popf` (중첩 안전). ISR 안에서 잠가도 IF 는 이미 0.
- 기본 설정(ConfMan, `OSystem_DOS::initBackend`): `opl_driver=dosopl`, `music_driver` 는 건드리지 않는다(SCI 는 사용자가 고른 adlib/mt32).
  출력 레이트 22050 Hz, 16비트 스테레오(SB16), 버퍼 1024 샘플.
- `BLASTER` 파싱: `A<hex>` 포트, `I<dec>` IRQ, `D<dec>` DMA, `H<dec>` 16비트 DMA, `P<hex>` MPU 포트, `T<dec>` 타입. 없으면 A220 P330. OPL 은 `A+8`(=0x228)
  또는 0x388 에서, OPL3 는 `A`/`A+2` 에서 감지.
- OPL 쓰기 지연: 주소 쓰기 후 상태 포트 6회, 데이터 쓰기 후 35회 읽기.
- 판정 기준 (spec §8 M3): KQ1 타이틀 곡의 key-on 시각이 이상적 틱 시각(첫 key-on 기준, 음악 틱 주기) 대비 편차 중앙값 ≤ 2 ms, 최대 ≤ 10 ms, 방 로딩 구간 최대 ≤ 20 ms.
  같은 곡의 (레지스터, 값) 순서는 리눅스 빌드(에뮬레이트 OPL)와 같다.

### Task 1: 순수 로직 — BLASTER 파싱과 PIT 체인 결정

- `blaster.h` (namespace DOS): `struct BlasterConfig { uint16 port = 0x220; int irq = 5; int dma = 1; int hdma = -1; uint16 mpu = 0x330; int type = 0; bool present = false; }`,
  `BlasterConfig parseBlaster(const char *s)` — 공백 구분 토큰, 대소문자 무시, 모르는 토큰 무시, 잘못된 숫자는 기본값 유지, `s == nullptr` 이면 기본값과 `present=false`.
- `pit-chain.h`: `struct PitChain { uint32 acc = 0; }`, `bool pitTick(PitChain &c, uint32 divisor = 1193)` — `acc += divisor; if (acc >= 65536) { acc -= 65536; return true; } return false;`
  (true = BIOS 로 체인). 상수 `kPitDivisor = 1193`, `kPitHz = 1193182 / 1193`.
- 테스트: `"A220 I7 D1 H5 P330 T6"` 전부; `"a240 p300"` 소문자; 빈 문자열/nullptr; `"A22G"` 잘못된 16진 → 기본 0x220; 55,000 틱 동안 체인 횟수가 `55000*1193/65536` 의 내림 또는 올림; 첫 체인이 55번째 틱.
- 커밋: `DOS: Parse BLASTER and decide when IRQ0 chains to the BIOS` / `TEST: ...`.

### Task 2: 선점형 타이머와 cli 뮤텍스

- `DosMutexInternal : Common::MutexInternal` — `lock()` = 저장된 EFLAGS 를 스택처럼 보관하고 `cli`; `unlock()` = 복원(`popf`). 재귀 잠금 허용(깊이 카운트 + 첫 잠금의 IF 만 저장).
- `DosTimerManager : DefaultTimerManager`:
  - 생성자에서 IRQ0 설치: `_go32_dpmi_get_protected_mode_interrupt_vector(8, &old)`, iret 래퍼로 ISR 설치, PIT `0x36` 모드 2/3 + 분주 1193, `atexit` 해제 등록.
  - ISR: 틱 카운터++ (`volatile uint32 g_ticks` — `getMillis()` 가 쓴다), `pitTick` 로 체인/EOI, 재진입 가드(`g_inHandler`) 아래에서 FPU 저장 → `handler()` 가 밀린 틱만큼
    (`DefaultTimerManager` 는 경과 시간을 `getMillis()` 로 본다 — 한 번 부르면 됨) → FPU 복원.
  - `handler()` 호출 빈도: 매 틱(1 kHz) 은 과하다 — 4 틱(≈4 ms)마다 부른다(상수, 주석으로 근거). SCI 음악 60 Hz·OPL RealChip 콜백 해상도에 충분.
  - 해제: PIT 기본 분주(0), 원래 벡터 복원, 래퍼 해제; idempotent.
  - 잠금: ISR 코드 범위와 정적 데이터 `_go32_dpmi_lock_code/_data`; `main()` 에서 `_CRT0_FLAG_LOCK_MEMORY` 를 지우던 줄을 없앤다(Global Constraints ruling, 주석 갱신).
- `OSystem_DOS`: `createMutex()` → `DosMutexInternal`; `_timerManager = new DosTimerManager()`; `getMillis()` → DOS 틱 카운터(ms); `pollEvent()` 의 `checkTimers()` 호출을 없앤다
  (ISR 이 부른다); `delayMillis()` 는 SDL_Delay 그대로(협력 스레드 양보).
- 검증: DOS 전용 설정 `dos_timer_selftest=true` 이면 `initBackend` 끝에서 3 초 동안 60 Hz 타이머 프로시저 하나를 걸고, 그동안 메인 스레드는 **양보 없이** 바쁜 루프(파일 읽기 포함)를
  돌린 뒤 로그에 `DOS: timer selftest 60Hz calls=<n> expect=180 getMillis=<ms> bios=<delta>` 를 남긴다. 기준: calls 178–182, getMillis 2980–3020, bios 53–56.
  두 에뮬레이터. M0/M1/M2 수락이 그대로 PASS.
- 커밋: `DOS: Preemptive timers on a 1 kHz IRQ0 that chains the BIOS` / `DOS: A mutex that holds interrupts off` / `DOS: Keep every allocation locked for interrupt handlers`.

### Task 6: M3 수락 테스트

`harness/dos/m3_accept.py <emu>`:
1. DOSBox 설정에 `[sblaster] sbtype=sb16 oplmode=opl3`, `[midi] mpu401=uart mididevice=none`, `cycles=60000`(두 에뮬레이터 문법 확인).
2. KQ1 (영어 원본이면 충분 — 음악은 언어와 무관) 을 `music_driver=adlib opl_driver=dosopl` 로 띄워 타이틀 곡 20 초 + 방 1 진입(로딩) 을 포함한 구간의 key-on 로그 수집.
   음악 틱 주기는 로그에서 추정하지 말고 SCI 음악 타이머 주기(60 Hz, 16.667 ms)를 쓴다: 각 key-on 의 시각을 가장 가까운 이상적 틱 격자(첫 key-on 기준)와 비교한 편차.
   기준: 중앙값 ≤ 2 ms, 최대 ≤ 10 ms, 방 로딩 구간(`wait_room` 전후로 하네스가 표시) 최대 ≤ 20 ms.
