2. **`SvfFont::drawChar` writes transparent AA edge pixels (bit 15 = 0) on `ARGB1555` surfaces**
   - **Location**: [svffont.cpp:52-65](file:///home/thkim/work/tmp/scummvm-review-aa/graphics/fonts/svffont.cpp#L52-L65)
   - **Failure scenario**: SDL2 advertises `ARGB1555` (`aBits == 1`, `aLoss == 7`, `aShift == 15`) as its 15-bit format ([surfacesdl-graphics.cpp:150](file:///home/thkim/work/tmp/scummvm-review-aa/backends/graphics/surfacesdl/surfacesdl-graphics.cpp#L150)). When `SvfFont::drawChar` draws opaque AA text (`p->a = 255`) onto a transparent (`a = 0`) `ARGB1555` surface, `plotPixel` computes `a = blendChannel(0, 255, cov)` and packs via `dst->format.ARGBToColor(r, g, b, a)`, which truncates `a >> 7`. Every pixel with `cov < 128` — including all 2 bpp `cov = 85` anti-aliased edge pixels — gets `alpha = 0` (bit 15 = 0, fully transparent), causing AA fringes to vanish when the surface is alpha-blitted or keyed.    - **Fix**: When `aBits == 1` (or for any non-zero coverage over transparent background when alpha is 1-bit), force opaque alpha (`a = 255` for `cov > 0`, or round `(a + 127) >> 7` / use `RGBToColor` when `p->a == 255` and `dst->format.aBits() == 1`). Add an `ARGB1555` test case to `test_svfFontSurfaces`.
