### Critical Findings

#### 1. `DosMutexInternal::unlock()` uses `popfl` to restore IF — hangs on `IOPL < CPL` DPMI hosts
- **Location**: [dos-mutex.cpp:41-49](file:///home/thkim/work/tmp/scummvm-review-p7/backends/mutex/dos/dos-mutex.cpp#L41-L49)
- **Failure scenario**: On x86 protected mode when `IOPL < CPL` (e.g., Windows 9x DOS box, NTVDM, OS/2, or VCPI/EMM386 ring-3 DPMI hosts), `popfl` does **not** fault and silently ignores bit 9 (`IF`), leaving interrupts permanently disabled after the first `Common::Mutex::unlock()`. The timer, Sound Blaster, and keyboard stop, hanging the process. Every other IRQ lock in this backend ([dos-heap.cpp:104-107](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-heap.cpp#L104-L107), [dos-loading.cpp:169-172](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-loading.cpp#L169-L172), [dos.cpp:1138-1139](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos.cpp#L1138-L1139)) and SDL3 patch `0010` explicitly replaced `popfl` with `if (flags & 0x200) sti` for this exact reason. Additionally, `unlock()` reads/decrements `g_lockDepth` without `cli` (safe only when balanced; an unbalanced call races with IRQ0).
- **Fix**: Replace `pushl %0; popfl` with `if (flags & 0x200) __asm__ __volatile__("sti" : : : "memory");`, and guard the `g_lockDepth` check/decrement with `cli` (or assert interrupts are already disabled when `g_lockDepth > 0`).

#### 2. 8.3 savefile mapping causes silent save corruption/destruction on `renameSavefile()`/`copySavefile()` and target collisions
- **Location**: [dos-savefile.h:100-140](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-savefile.h#L100-L140), [dos-savenames.h:36-58](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-savenames.h#L36-L58), inherited [savefile.cpp:82-125](file:///home/thkim/work/tmp/scummvm-review-p7/backends/saves/savefile.cpp#L82-L125)
- **Failure scenario**:
  1. **Destructive `renameSavefile()` / `copySavefile()`**: `DOS::SaveFileManager` inherits `SaveFileManager::copySavefile()`, which opens `oldFilename` for reading and—*before reading any bytes*—calls `openForSaving(newFilename)` (`fopen("wb")`). `renameSavefile()` then calls `removeSavefile(oldFilename)`. Whenever `dosPattern(oldFilename).equalsIgnoreCase(dosPattern(newFilename))` (e.g., renaming between two >8-char targets sharing a prefix or >3-char extensions like `.sav1` → `.sav2`), `openForSaving` truncates the single underlying 8.3 file to 0 bytes and `removeSavefile` deletes it—destroying the save.
  2. **Silent cross-target overwrite/deletion**: Two targets sharing their first 8 characters (e.g., `kq1-rgb565` & `kq1-rgb555`, `laurabow-en` & `laurabow-ko`, `monkey1-vga` & `monkey1-ko`) map to the same file (`KQ1-RGB5.001`). Saving or deleting in one target silently overwrites or deletes the other's saves, and `listSavefiles()` exposes the other target's slots (risking loading an incompatible game state). Unlike `stage-data.py`, there is no collision detection or warning.
  3. **`dosPattern()` edge cases**:
     - Multi-dot names (e.g., `kq1.v1.001`, `monkey.cd.001`) split on `findLastOf('.')` only, leaving two dots in the base (`kq1.v1.001`), which MS-DOS cannot open as-is (it truncates at the *first* dot), desynchronizing `DefaultSaveFileManager`'s cache from the filesystem.
     - `dosPattern()` only checks `!contains('*')`, ignoring `?` and `#` wildcards (asymmetric with `engineName()` at line 53, which checks `*`, `?`, `#`), and a dotless wildcard pattern like `"kq1-rgb565*"` is left un-truncated so it never matches `KQ1-RGB5.001`.
- **Fix**: Override `copySavefile()` and `renameSavefile()` in `DOS::SaveFileManager` to detect `dosPattern(oldName).equalsIgnoreCase(dosPattern(newName))` (no-op or copy via buffer/temp 8.3 name before replacing). Strip/collapse extra dots in `dosPattern()` and guard `?`/`#` consistently with `engineName()` (and truncate prefix before `*` when length > 8). For long-target collisions, either hash/disambiguate >8-char bases deterministically (e.g., 5 chars + 3-char base36 hash of the full base) with a mapping table or at minimum detect and warn/refuse colliding targets when sharing a save directory.

#### 3. Palette-only frames pass `(nullptr, 0)` to `SDL_UpdateWindowSurfaceRects()` — CLUT8 fades/cycling fail to update VGA DAC
- **Location**: [dos-graphics.cpp:549-576](file:///home/thkim/work/tmp/scummvm-review-p7/backends/graphics/dos/dos-graphics.cpp#L549-L576)
- **Failure scenario**: During a CLUT8 palette fade-in/fade-out or palette cycling when no screen pixels are dirty and the software cursor is hidden or stationary (e.g., SCI/SCUMM/AGI title fades and cutscenes), `_paletteDirty` is `true` while `send` is empty. Line 575 executes `SDL_UpdateWindowSurfaceRects(_window, nullptr, 0)`. SDL3's `SDL_UpdateWindowSurfaceRects()` validates `rects != NULL` and `numrects > 0` and immediately returns `false` (`SDL_InvalidParamError`) without calling the DOS video driver's `UpdateWindowFramebuffer`, so the updated `SDL_Palette` is never programmed into the VGA DAC and the fade freezes until pixels change or the mouse moves.
- **Fix**: When `_paletteDirty && rects.empty()`, either call `SDL_UpdateWindowSurface(_window)` or push a minimal 1×1 rect `{0, 0, 1, 1}` so the driver's `UpdateWindowFramebuffer` runs and reprograms the VGA DAC.

#### 4. `dos-heap.cpp`: Out-of-bounds read on arbitrary/`sbrk` pointers and DPMI memory calls from ISR context
- **Location**: [dos-heap.cpp:109-116](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-heap.cpp#L109-L116), [dos-heap.cpp:128-171](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-heap.cpp#L128-L171), [dos-heap.cpp:187-198](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-heap.cpp#L187-L198), [dos-heap.cpp:224-239](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/dos-heap.cpp#L224-L239)
- **Failure scenario**:
  1. **OOB read / false-positive DPMI free**: `largeHeader(ptr)` checks only `((uintptr)ptr & 4095) == 32` and dereferences `(LargeHeader *)ptr - 1`. Any `sbrk` allocation that happens to land at page offset `0x20` causes `free()`/`realloc()` to read 32 bytes *before* the allocation (potentially another chunk, freed memory, or an uncommitted page at the start of an `sbrk` region). Even worse, `dosHeapInLargeBlock(ptr, size)` unconditionally reads `*(LargeHeader *)((uintptr)ptr & ~4095)` for *any* non-null pointer (stack, static, or `sbrk`), which can page-fault if the start of that page is unmapped or false-positive on the weak 32-bit XOR check (causing `free()` to pass garbage to `__dpmi_free_memory()`).
  2. **DPMI allocation/free inside IRQ0 ISR**: `__wrap_malloc`, `__wrap_calloc`, `__wrap_realloc`, `__wrap_memalign`, and `__wrap_free` invoke `largeAlloc()` / `largeFree()` (`__dpmi_allocate_memory`, `__dpmi_lock_linear_region`, `__dpmi_free_memory`) without checking whether interrupts are enabled. If a timer proc inside IRQ0 (or code holding a `Common::Mutex`) allocates ≥ 256 KB or frees a ≥ 256 KB block, it calls non-reentrant DPMI 0.9 memory management functions from a hardware interrupt handler, risking host corruption or crash.
- **Fix**:
  1. Validate large-block ownership by walking `g_largeList` under `heapLock()` (the list holds only ≥ 256 KB allocations—typically a handful of entries) instead of blindly reading memory before `ptr` or at `page + 0`. Keep the `((uintptr)ptr & 4095) == sizeof(LargeHeader)` fast filter before walking `g_largeList` in `largeHeader()`.
  2. In `largeAlloc()`, check `interruptsEnabled()` (from `pushfl`) and return `nullptr` (falling back to `smallAlloc()`) if interrupts are off. In `largeFree()`, if interrupts are off, push the block onto a `g_deferredLargeFree` list and call `__dpmi_free_memory()` on the next allocation/free with interrupts enabled.

Unlike `PrefetchMixer::getOutputLatencyMillis()` (which guards via `_guard()`), `DosMixerManager::fillStats()` calls `DOS_SBGetStats()` without checking `interruptsEnabled()`, so any exit/shutdown path reached with interrupts disabled will have interrupts re-enabled unexpectedly.
- **Fix**: Validate `channel` (`0..3` for low DMA, `5..7` for high DMA) before indexing page-port tables in SDL3 patch 0007. Guard `DOS_SBGetStats()` with an `interruptsEnabled()` check (or save/restore IF via `if (flags & 0x200) sti` inside `DOS_SBGetStats()`).

#### 13. In-place `SCUMMVM.INI` writes risk full config loss on crash/disk-full
- **Location**: [stdiostream.cpp:50-53](file:///home/thkim/work/tmp/scummvm-review-p7/backends/fs/stdiostream.cpp#L50-L53), [play.cpp:187-200](file:///home/thkim/work/tmp/scummvm-review-p7/backends/platform/dos/launcher/play.cpp#L187-L200)
- **Failure scenario**: Defining `STDIOSTREAM_NO_ATOMIC_SUPPORT` for `__DJGPP__` avoids failing on `NAME.EXT.tmp`, but truncates `SCUMMVM.INI` immediately with `fopen(..., "wb")`. A disk-full condition or crash/power loss mid-write leaves an empty/corrupt INI. In `PLAY.EXE`, `replaceFile()` writes to `SCUMMVM.NEW` first (good), but calls `remove(path)` before `rename(tmp, path)`; a crash/power loss in that window leaves the user without their INI (`SCUMMVM.NEW` left behind).
- **Fix**: For `StdioStream` on DJGPP, consider using an 8.3 sibling temp file (e.g., replacing extension with `.TMP` / `SCUMMVM.$$$`) when writing config files, or document the in-place write limitation in `README.md`. In `PLAY.EXE`, recover from a stray `SCUMMVM.NEW` if `USER.INI`/`SCUMMVM.INI` is missing on startup.
